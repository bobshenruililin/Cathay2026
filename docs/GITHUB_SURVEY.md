# Survey how-to

This is the index essay. The database is `docs/survey/projects/*.md`.
Drive it with `.cursor/skills/compound/SKILL.md`. Do not copy surveyed code.

## Winner pattern (Cathay + SIA)

Named Business Unit, one job, one object, a prototype that runs, a path into
the airline (intern / Innovate / named feed). 2025: Kairos named **HK Express**;
FlyLab paired **pilots + IT** and used Gemini to summarise, not to decide.
2024 GingTrip: trolley + dashboard. 2023 NAAR: cargo labour. 2017 TouchCX:
crew tablet. SIA SQXP: one named journey (Stopover Holidays).

Student GitHub that did **not** win is full of chatbots and miles visualisers.
Do not join that field.

## GitHub IROPS pattern

Useful repos freeze the decision core, name the desk, and run offline.
Typical clones put Gemini in the cockpit with Kafka and a map. Steal quiet
default, mock/live parity, adversarial drafts, and a number from **our sim**.
Do not steal the super-app stack.

## Aviation bar

SpaceX: test like you fly; HITL every change; no second decision brain.
NASA F Prime: depend on port types, not sibling internals.
NASA Open MCT: unit + e2e + visual + perf — keep Playwright; do not embed.
Amadeus Passenger Recovery: mass rebook in Altéa. We are the HKG transfer
slice **before** `PNR_AddMultiElements`.

## Anti-patterns

`airline-disruption-ai`, FlightFixer: event-bus theatre. `otaip` is honest
industry language (ATPCO/IRROPS) — cite in Q&A, never import fare construction.

## Ingest rule

A new URL becomes a card with `well` / `poor` / `steal` / `never` filled from
primary sources (README, press). `status: seed` until a human or a refresh
pass marks `reviewed`. Then apply the skill ladder once.
